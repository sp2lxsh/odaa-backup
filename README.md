# ODAA Backup — локальные копии сайтов с хостингов

Программа для Windows 11, которая сама скачивает резервные копии ваших сайтов
с хостингов (Beget, Reg.ru, Timeweb Cloud и любых других с SSH) **на ваш компьютер**.

Зачем: когда хостинг атакуют, его собственные бэкапы тоже недоступны. Правило **3-2-1**:
3 копии данных, на 2 разных носителях, 1 — вне хостинга. Эта программа делает копию
«вне хостинга» и при желании вторую — на внешний диск или в облачную папку.

**Что нужно от вас — только логин и пароль от хостинга.** Программа сама:

* находит сайты (WordPress, Joomla, 1С-Битрикс, OpenCart, Node.js-приложения и обычные сайты);
* находит базы данных и берёт их пароли из настроек сайта (`wp-config.php` и т.п.) —
  вводить пароли баз не нужно, и смена пароля базы ничего не ломает;
* скачивает **только изменившиеся** файлы — каждая копия выглядит полной, но почти не занимает места;
* проверяет копии (контрольные суммы SHA-256, целостность дампов баз);
* хранит 3 последних + 7 ежедневных + 4 еженедельных + 6 ежемесячных копий;
* работает по расписанию сама, даже когда окно программы закрыто;
* **никогда ничего не меняет и не удаляет на серверах** — только читает.

## 1. Установка

1. Откройте страницу репозитория на GitHub → вкладка **Actions** → последняя успешная сборка
   **build-windows-exe** → внизу блок **Artifacts** → скачайте `odaa-backup-windows`.
   Если Chrome блокирует скачивание («опасный файл»), скачайте через **Microsoft Edge**
   (там будет кнопка «Сохранить» → «Всё равно сохранить»). Это ложная тревога: программа
   не подписана платным сертификатом, весь её код открыт в этом репозитории.
2. Распакуйте архив. Внутри — папка **`ODAA Backup`**. Перенесите её целиком на диск,
   например в `C:\ODAA Backup`. Лучше сразу постоянное место: автоматическое копирование
   запоминает, где лежит программа.
3. Откройте папку и дважды щёлкните **`odaa-backup.exe`**. Откроется чёрное окно и браузер
   с окном программы. Папку `_internal` не трогайте — это части программы.

> Если Windows покажет «Система Windows защитила ваш компьютер», нажмите «Подробнее» →
> «Выполнить в любом случае». Если Защитник Windows удалил файл: «Безопасность Windows» →
> «Защита от вирусов и угроз» → «Журнал защиты» → запись про odaa-backup → «Разрешить на устройстве».

Чёрное окно не закрывайте, пока работаете в браузере. Автоматическое копирование работает и без него.
Если раньше уже запускали старую версию — сначала закройте её чёрное окно.

## 2. Добавление хостинга

Нажмите **«＋ Добавить хостинг»** и выберите, где сайт:

| Хостинг | Что ввести | Где взять |
|---|---|---|
| **Beget** | логин и пароль | те же, что для входа в панель Beget |
| **Reg.ru** | сервер, логин, пароль | Личный кабинет → Хостинг → услуга → вкладка «Доступы» |
| **VPS** (Timeweb и др.) | IP-адрес, пользователь (`root`) | панель VPS; если входите по ключу — пароль оставьте пустым, ключ из `C:\Users\вы\.ssh` найдётся сам |

Нажмите **«Подключиться и найти сайты»**. Программа покажет найденные сайты и базы данных —
отметьте нужные, выберите, как часто копировать, и нажмите **«Добавить и сделать первую копию»**.
Всё: первая копия начнёт скачиваться, а автоматическое копирование включится само.

Пароль от хостинга сохраняется в **Диспетчере учётных данных Windows**, а не в файлах программы.

## 3. Окно программы

* **Сайты** — карточка на каждый сайт: всё ли в порядке, когда была последняя копия, размер,
  когда будет следующая. Переключатель **Вкл/Выкл**, кнопка **«Скачать сейчас»**.
* **Подробнее** (страница сайта) — как часто копировать, сколько копий хранить, список всех копий
  с кнопками **«Проверить»** (сверка контрольных сумм) и **«Открыть»** (папка в Проводнике),
  «Проверить подключение», смена пароля, удаление источника.
* **Настройки** — папка для копий, вторая копия, Telegram, автоматическое копирование.
* **Журнал** — последний отчёт и подробности работы.

## 4. Вторая копия и уведомления

**Вторая копия.** Основная копия на одном диске не защищает от поломки диска, кражи ноутбука
или вируса-шифровальщика. В **Настройках → Вторая копия** выберите внешний диск или папку
Яндекс.Диска / OneDrive. После каждой успешной копии программа положит туда архив,
зашифрованный паролем (нужен бесплатный [7-Zip](https://7-zip.org)). **Запишите пароль
архива на бумаге** — без него архив не открыть.

**Telegram.** В **Настройках → Уведомления в Telegram**: создайте бота у @BotFather, напишите
ему любое сообщение, узнайте свой chat_id у @userinfobot, введите токен и chat_id.
Кнопка «Отправить тест» проверит, что всё работает.

## 5. Где лежат копии

```
D:\Backups\
  beget\                     ← провайдер
    beget-mysite\            ← источник (id)
      2026-11-12_0300\       ← снимок (дата_время)
        files\mysite\...     ← файлы сайта как есть
        db\mylogin_wp.sql.gz ← дамп базы (сжатый)
        manifest.sha256      ← контрольные суммы всех файлов
        snapshot.json        ← итог: сколько файлов, что скачано, ошибки
        api_backups.json     ← список бэкапов на стороне хостинга (если есть API)
C:\OdaaBackup\data\
  logs\odaa-backup.log       ← журнал
  reports\last_report.txt    ← последний отчёт
  known_hosts                ← проверенные отпечатки серверов
  state.json, overrides.json ← состояние и настройки из окна управления
```

Каждый снимок выглядит как **полная** копия, но неизменённые файлы — это «жёсткие ссылки»
на тот же файл в прошлом снимке, поэтому 17 снимков сайта на 5 ГБ занимают примерно
5 ГБ + объём изменений. Удалять старые снимки вручную безопасно — остальные не пострадают
(программа и сама удаляет лишние по правилам хранения).

Если в имени файла на сервере есть символы, запрещённые в Windows (`: ? * " < > |`),
они заменяются кодом, например `a:b.txt` → `a%3Ab.txt`. Список таких файлов — в `snapshot.json`.

## 6. Восстановление из копии

Сначала проверьте снимок: окно управления → сайт → «Проверить» (или
`odaa-backup.exe verify ИСТОЧНИК ИМЯ_СНИМКА`). Должно быть «все контрольные суммы совпали».

### Файлы сайта (Beget, Reg.ru)

1. Установите **WinSCP** (https://winscp.net) или FileZilla.
2. Подключитесь к хостингу (протокол SFTP, те же сервер/логин/пароль).
3. Скопируйте содержимое `снимок\files\ИМЯ\` в папку сайта на сервере
   (`mysite.ru/public_html` или `www/site.ru`).

### База данных MySQL

Файл `db\ИМЯ.sql.gz`:

* **Через phpMyAdmin** (есть в панелях Beget и Reg.ru): откройте базу → «Импорт» →
  выберите файл `.sql.gz` (phpMyAdmin понимает сжатые файлы). Если файл слишком большой
  для импорта — распакуйте его 7-Zip и загрузите по частям, или используйте способ ниже.
* **Через SSH**: загрузите файл на сервер (WinSCP) и выполните
  ```bash
  gunzip -c ИМЯ.sql.gz | mysql -u ПОЛЬЗОВАТЕЛЬ -p ИМЯ_БАЗЫ
  ```

Если сайт переезжает на **новый хостинг**: восстановите файлы и базу, затем в `wp-config.php`
поменяйте имя базы, пользователя, пароль и хост на новые.

### VPS Timeweb (сервис vybor)

1. Создайте/переустановите VPS, установите Node.js и nginx.
2. Через WinSCP скопируйте `files\vybor\` → `/opt/vybor` (включая `storage` и `.env`),
   `files\systemd\vybor.service` → `/etc/systemd/system/`,
   `files\nginx-sites\` → `/etc/nginx/sites-available/` (и ссылки в `sites-enabled`).
3. На сервере:
   ```bash
   cd /opt/vybor && npm ci --omit=dev
   systemctl daemon-reload && systemctl enable --now vybor
   nginx -t && systemctl reload nginx
   ```

### Из зашифрованной второй копии

Откройте `.7z` архив в 7-Zip, введите пароль архива — внутри тот же снимок.

## 7. Безопасность

* Пароли и токены хранятся **только** в Диспетчере учётных данных Windows
  (Панель управления → Диспетчер учётных данных → Учётные данные Windows → `odaa-backup`).
* Пароли баз данных нигде не сохраняются — они читаются из настроек сайта в момент копирования.
* Пароли не попадают в журнал и отчёты (вырезаются автоматически).
* Пароль базы не передаётся в командной строке на сервере: `mysqldump` получает его через канал SSH.
* При добавлении хостинга программа запоминает «отпечаток» сервера. Если он потом изменится,
  копирование остановится, пока вы не подтвердите новый (защита от подмены сервера).
* Окно программы доступно только с этого компьютера (`127.0.0.1`) и защищено от действий с чужих сайтов.
* Программа только читает с серверов. Удаляет она только свои старые копии на вашем диске.
* С VPS копируется `.env` с секретами сервиса — включите шифрование второй копии.

## 8. Если что-то не работает

| Сообщение | Что делать |
|---|---|
| `Сервер не пустил: неверный логин или пароль` | Проверьте логин/пароль; для Reg.ru — включён ли SSH (на тарифе «Хост-Лайт» SSH нет). |
| `Сервер «…» не найден / не отвечает` | Проверьте адрес. Для Reg.ru — адрес из вкладки «Доступы». |
| `ключ … защищён паролем` | В «Дополнительно» введите пароль ключа. |
| `Отпечаток сервера … ИЗМЕНИЛСЯ` | Не подтверждайте сразу! Спросите поддержку хостинга, переустанавливали ли сервер. |
| `не удалось прочитать логин/пароль базы из wp-config.php` | Файл переименован или перемещён — проверьте сайт. |
| `mysqldump … Access denied` | Пароль базы в `wp-config.php` не подходит к базе — сайт тоже не работает? |
| `на сервере не найден mysqldump` | Напишите в поддержку хостинга; файлы при этом копируются. |
| `нет доступа к папке …` | Предупреждение: часть служебных папок закрыта хостингом. Обычно не страшно. |
| Окно программы не открывается | Откройте в браузере `http://127.0.0.1:8765`. |

Подробности всегда есть на странице **Журнал** и в файле `data\logs\odaa-backup.log`.

## 9. Особенности хостингов

* **Beget** — сервер определяется сам (`логин.beget.tech`). Можно указать API-пароль
  (панель → «API») в «Дополнительно» — тогда программа покажет и копии, которые хранит сам Beget.
* **Reg.ru** — SSH есть на всех тарифах, кроме «Хост-Лайт». Подключаться можно только под основным
  логином хостинга (`u1234567`).
* **Timeweb Cloud VPS** — программа найдёт проекты в `/opt`, `/var/www`, `/srv`, а также предложит
  настройки nginx, службы systemd и задания cron. В «Дополнительно» можно указать API-токен —
  программа покажет копии дисков VPS у Timeweb.

## 10. Для опытных: config.yaml и команды

Всё настраивается в окне программы. Файл `config.yaml` рядом с программой **необязателен** —
он нужен, только если хочется описать источники вручную (пример — `config.example.yaml`).
Источники из файла и из окна программы работают вместе. Пути Windows пишите в одинарных
кавычках: `'D:\Backups'`.

Команды (`odaa-backup.exe КОМАНДА`):

```
(без команды) | ui     окно программы в браузере
menu                   текстовое меню в консоли
run [--source ID] [--dry-run] [--scheduled]
status | setup | check | keygen
trust ID | test ID | verify ID [СНИМОК]
secret set|delete|list [ИМЯ]
schedule install|remove|status
```

## 11. Для разработчика

Python 3.12+, зависимости: `paramiko` (SSH/SFTP), `keyring` (Диспетчер учётных данных), `PyYAML`.
Интерфейс — встроенный `http.server`, без внешних фреймворков.

```
odaa_backup/
  cli.py          меню и команды
  config.py       разбор и проверка config.yaml, overrides из интерфейса
  schedule.py     расписание по источникам, задача Планировщика Windows
  runner.py       выполнение: снимок → файлы → дампы → манифест → ротация → 2-я копия → отчёт
  sync.py         инкрементальная загрузка по SFTP (жёсткие ссылки, докачка, повторы, лимит скорости)
  ssh.py          подключение, проверка отпечатков (known_hosts), sha256sum на сервере, генерация ключа
  mysql.py        mysqldump через SSH → .sql.gz, проверка дампа
  manifest.py     манифест SHA-256 и проверка снимка
  retention.py    ротация last/daily/weekly/monthly
  apis.py         списки бэкапов Beget / Timeweb Cloud / ISPmanager (только чтение)
  archive.py      вторая копия (7-Zip AES-256)
  report.py       отчёт и Telegram
  webui.py        окно программы (127.0.0.1): мастер, сайты, настройки
  discover.py     автопоиск сайтов, баз и паролей баз из конфигов CMS
  static/         шрифт Inter Tight (SIL OFL)
  secretstore.py  пароли в keyring, вырезание секретов из логов
tests/            тесты: целостность, ротация, конфиг, расписание, синхронизация
```

Запуск из исходников и тесты:

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m odaa_backup --config config.yaml run --dry-run
```

Команды:

```
odaa-backup run [--source ID] [--dry-run] [--scheduled]
odaa-backup ui | status | setup | check | keygen | init
odaa-backup trust ID | test ID | verify ID [СНИМОК]
odaa-backup secret set|delete|list [ИМЯ]
odaa-backup schedule install|remove|status
```

Сборка (папка `ODAA Backup` с двумя .exe, см. `odaa-backup.spec`): `build.bat` на Windows или GitHub Actions (`.github/workflows/build.yml`)
при каждом push; для тега `v*` создаётся релиз с zip-архивом.
