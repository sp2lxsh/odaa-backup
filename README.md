# ODAA Backup — локальные копии сайтов с хостингов

Программа для Windows 11, которая сама скачивает резервные копии ваших сайтов
с хостингов (Beget, Reg.ru, Timeweb Cloud и любых других с SSH) **на ваш компьютер**.

Зачем: когда хостинг атакуют, его собственные бэкапы тоже недоступны. Правило **3-2-1**:
3 копии данных, на 2 разных носителях, 1 — вне хостинга. Эта программа делает копию
«вне хостинга» и при желании вторую — на внешний диск или в облачную папку.

Что программа умеет:

* копирует файлы сайтов по SFTP: **только изменившиеся** файлы, остальные берёт из прошлой копии (место на диске не тратится);
* снимает дампы баз MySQL (`mysqldump` через SSH) и проверяет их;
* для каждой копии составляет список контрольных сумм SHA-256 и проверяет файлы;
* хранит 3 последних + 7 ежедневных + 4 еженедельных + 6 ежемесячных копий (настраивается);
* работает по расписанию (Планировщик Windows создаётся одной кнопкой);
* показывает **окно управления** в браузере: состояние каждого сайта, последняя копия,
  кнопка «Скачать сейчас», включение/выключение и частота копирования для каждого сайта;
* присылает отчёт в Telegram (по желанию);
* **никогда ничего не меняет и не удаляет на серверах** — только читает.

## 1. Установка

### Вариант А (проще): готовая программа

1. Откройте страницу репозитория на GitHub → вкладка **Actions** → последняя успешная сборка
   **build-windows-exe** → внизу блок **Artifacts** → скачайте `odaa-backup-windows`.
   (Если в репозитории есть раздел **Releases** — можно скачать zip оттуда.)
2. Создайте папку, например `C:\OdaaBackup`, и распакуйте туда файлы:
   `odaa-backup.exe`, `odaa-backup-bg.exe`, `config.example.yaml`, `README.md`.
3. Готово, устанавливать ничего не нужно.

> Windows может показать «Система Windows защитила ваш компьютер» — программа не подписана
> сертификатом. Нажмите «Подробнее» → «Выполнить в любом случае».

### Вариант Б: собрать самому

1. Установите Python 3.12 или новее с https://python.org (при установке поставьте галочку
   **Add python.exe to PATH**).
2. Скачайте код (кнопка **Code → Download ZIP**), распакуйте.
3. Дважды щёлкните `build.bat`. Через несколько минут в папке `dist` появятся
   `odaa-backup.exe` и `odaa-backup-bg.exe`. Скопируйте папку `dist` в `C:\OdaaBackup`.

Команда сборки (то же, что делает `build.bat`):

```bat
pyinstaller --noconfirm --onefile --console --name odaa-backup --add-data "config.example.yaml;." --hidden-import keyring.backends.Windows launcher.py
pyinstaller --noconfirm --onefile --windowed --name odaa-backup-bg --add-data "config.example.yaml;." --hidden-import keyring.backends.Windows launcher.py
```

`odaa-backup-bg.exe` — та же программа, но без чёрного окна; её запускает Планировщик.

### Дополнительно (по желанию)

* **7-Zip** (https://7-zip.org) — нужен только для зашифрованной второй копии.

## 2. Подготовка доступов на хостингах

Программе нужен доступ по **SSH/SFTP** (это «защищённый вход» на сервер) и пароли к базам данных.

### Beget

1. Панель Beget → раздел **SSH** → включите доступ по SSH. Сервер обычно `ВАШ_ЛОГИН.beget.tech`,
   логин — логин аккаунта, пароль — пароль аккаунта (или отдельный, если задан).
2. Раздел **MySQL** → для каждой базы запомните имя (например `mylogin_wp`). На Beget имя
   пользователя базы совпадает с именем базы. Пароль — тот, что задавали при создании базы
   (если забыли — его можно сменить там же, но тогда поменяйте и в `wp-config.php` сайта!).
   Подсказка: пароль базы WordPress записан в файле `public_html/wp-config.php`, строка `DB_PASSWORD`.
3. (По желанию) раздел **API** → включите API и задайте API-пароль. Тогда в отчёте будет виден
   список бэкапов, которые хранит сам Beget.
4. Папка сайта обычно `ИМЯ_САЙТА/public_html` (от домашней папки).

### Reg.ru (виртуальный хостинг с ISPmanager)

1. Личный кабинет Reg.ru → услуга хостинга → **Доступы** (или «Информация о доступах»):
   там указаны сервер (например `server123.hosting.reg.ru`), логин (`u1234567`) и пароль.
   Если SSH выключен — включите его в разделе управления хостингом («Доступ по SSH»).
2. В ISPmanager → **Базы данных**: имя базы и пользователя (обычно `u1234567_...`).
   Пароль базы также есть в `wp-config.php`.
3. Папка сайта обычно `www/ИМЯ_САЙТА`.

### Timeweb Cloud (VPS)

1. Для VPS удобнее вход по **SSH-ключу**. Если у вас уже есть ключ, которым вы заходите на сервер,
   укажите путь к нему в `key_file`. Если нет — в меню программы выберите пункт
   **9 «Создать SSH-ключ»**: программа создаст ключ и покажет строку, которую нужно добавить
   в панели Timeweb (Сервер → SSH-ключи) или в файл `/root/.ssh/authorized_keys` на сервере.
2. (По желанию) панель Timeweb Cloud → **API и Terraform** → создайте токен. Тогда в отчёте
   будет виден список бэкапов дисков VPS, которые хранит Timeweb.

## 3. Заполнение настроек (config.yaml)

1. Дважды щёлкните `odaa-backup.exe`. При первом запуске программа создаст `config.yaml`
   (копию примера) и откроет его в Блокноте.
2. Поменяйте значения под себя. В файле есть подсказки. Главное:
   * `backup_root` — куда складывать копии, например `"D:\\Backups"`
     (обратная косая черта пишется **двойной**);
   * для каждого сайта — блок `- id: ...` (см. ниже).
3. **Пароли в файл не пишутся!** Вместо пароля указывается его **имя**, например
   `password_secret: beget-ssh`. Сами пароли вы введёте на следующем шаге — они сохранятся
   в «Диспетчере учётных данных Windows».

Пример блока для сайта на Beget:

```yaml
  - id: beget-mysite            # короткое имя латиницей — это имя папки с копиями
    provider: beget
    title: "Сайт mysite.ru"
    schedule: "daily 03:00"     # когда копировать (можно менять в окне управления)
    ssh:
      host: mylogin.beget.tech
      user: mylogin
      password_secret: beget-ssh
    files:
      - remote: "mysite.ru/public_html"
        name: mysite
        exclude: ["wp-content/cache", "*.log"]
    mysql:
      databases:
        - name: mylogin_wp
          user: mylogin_wp
          password_secret: beget-db-mylogin_wp
```

Варианты расписания: `manual` (только вручную), `every 6h` (каждые 6 часов),
`daily 03:00` (каждый день в 3:00), `weekly sun 03:00` (по воскресеньям).

Что исключать (`exclude`):
`node_modules` — папка с таким именем на любом уровне; `*.log` — все файлы с таким окончанием;
`wp-content/cache` — конкретная папка от корня сайта.

Если в файле ошибка, программа покажет понятное сообщение с номером источника и параметром.

## 4. Первый запуск

Запустите `odaa-backup.exe` — откроется меню:

```
 1 — Открыть окно управления (в браузере)      ← удобнее всего
 2 — Скачать бэкапы всех сайтов сейчас
 3 — Пробный запуск (показать, что будет скачано)
 4 — Состояние и возраст копий
 5 — Первичная настройка (пароли, отпечатки серверов, проверка)
 6 — Создать задачу в Планировщике Windows (автоматически)
 7 — Проверить целостность последних снимков
 8 — Открыть config.yaml в Блокноте
 9 — Создать SSH-ключ (вход без пароля)
 0 — Выход
```

Порядок действий в первый раз:

1. **Пункт 5 — Первичная настройка.** Программа по очереди спросит все пароли и токены
   (ввод не отображается — это нормально) и сохранит их в Диспетчере учётных данных Windows.
   Затем покажет **отпечаток** каждого сервера, например `SHA256:LI/R14bOKe+...`.
   Отпечаток — это «паспорт» сервера: он защищает от подмены. Если есть возможность —
   сверьте его с поддержкой хостинга; затем ответьте «да». В конце программа проверит
   подключение и наличие папок и `mysqldump`.
2. **Пункт 3 — Пробный запуск.** Покажет, сколько файлов и какого объёма будет скачано,
   ничего не скачивая.
3. **Пункт 2 — Скачать сейчас.** Первая копия скачивает всё (может занять время);
   следующие — только изменения.
4. **Пункт 6 — Расписание.** Дальше всё будет происходить автоматически.

## 5. Окно управления

Пункт меню **1** (или команда `odaa-backup.exe ui`) открывает в браузере страницу
`http://127.0.0.1:8765`. Она доступна **только с вашего компьютера**. Пока вы работаете
со страницей, не закрывайте чёрное окно программы.

На странице **«Сайты»**:

* статус каждого сайта (в порядке / внимание / проблема), когда была последняя копия, её размер;
* кнопки **«Скачать сейчас»**, **«Скачать всё сейчас»**, **«Пробный запуск»**;
* предупреждение, если копии лежат только на одном диске.

Кнопка **«Управление»** у сайта:

* **включить / выключить** копирование этого сайта;
* **как часто** копировать (каждый час … раз в неделю, или своё значение);
* **сколько копий хранить** (последних / ежедневных / еженедельных / ежемесячных);
* список всех снимков с результатом, кнопки **«Проверить»** (сверка контрольных сумм)
  и **«Открыть»** (папка в Проводнике);
* **«Проверить подключение»** и **«Проверить отпечаток»** сервера;
* список бэкапов, которые хранит сам хостинг (если подключён API).

Изменения из окна управления сохраняются в `data\overrides.json` и действуют сразу;
`config.yaml` при этом не меняется.

Страница **«Пароли»** — задать или заменить пароль/токен (посмотреть сохранённый нельзя).
Страницы **«Отчёт»** и **«Журнал»** — последний отчёт и подробный журнал работы.

## 6. Автоматическое расписание

Меню → **6**, или страница «Расписание» → **«Создать / обновить задачу»**, или команда:

```bat
odaa-backup.exe schedule install
```

Создаётся задача Планировщика Windows **«ODAA Backup»**, которая каждый час запускает
`odaa-backup-bg.exe` (без окна). Программа сама решает, какому сайту пора делать копию
по его расписанию. Если компьютер был выключен в назначенное время, копия будет сделана
при следующем включении. После ошибки повтор — не раньше чем через час.

Задача работает, когда вы вошли в Windows (так программе доступны пароли из Диспетчера
учётных данных). Компьютер не обязательно держать включённым круглые сутки — достаточно
включать его хотя бы раз в день.

Удалить задачу: `odaa-backup.exe schedule remove`.

## 7. Как добавить ещё один сайт

1. Откройте `config.yaml` (меню → 8).
2. Скопируйте целиком блок, начинающийся с `- id:`, вставьте его ниже, поменяйте
   `id` (должен быть уникальным), `title`, адреса, папки, базы и **имена** паролей.
3. Сохраните, запустите меню → 5 (ввести новые пароли и проверить сервер).

Ещё один сайт на том же аккаунте Beget можно добавить проще — второй строкой в `files:`
того же источника и второй базой в `databases:`.

Код программы менять не нужно.

## 8. Где лежат копии

```
D:\Backups\
  beget\                     ← провайдер
    beget-mysite\            ← источник (id)
      2026-11-12_0300\       ← снимок (дата_время)
        files\mysite\...     ← файлы сайта как есть
        db\mylogin_wp.sql.gz ← дамп базы (сжатый)
        manifest.sha256      ← контрольные суммы всех файлов
        snapshot.json        ← итог: сколько файлов, что скачано, ошибки
        api_backups.json     ← список бэкапов на стороне хостинга (если есть API)
C:\OdaaBackup\data\
  logs\odaa-backup.log       ← журнал
  reports\last_report.txt    ← последний отчёт
  known_hosts                ← проверенные отпечатки серверов
  state.json, overrides.json ← состояние и настройки из окна управления
```

Каждый снимок выглядит как **полная** копия, но неизменённые файлы — это «жёсткие ссылки»
на тот же файл в прошлом снимке, поэтому 17 снимков сайта на 5 ГБ занимают примерно
5 ГБ + объём изменений. Удалять старые снимки вручную безопасно — остальные не пострадают
(программа и сама удаляет лишние по правилам хранения).

Если в имени файла на сервере есть символы, запрещённые в Windows (`: ? * " < > |`),
они заменяются кодом, например `a:b.txt` → `a%3Ab.txt`. Список таких файлов — в `snapshot.json`.

## 9. Восстановление из копии

Сначала проверьте снимок: окно управления → сайт → «Проверить» (или
`odaa-backup.exe verify ИСТОЧНИК ИМЯ_СНИМКА`). Должно быть «все контрольные суммы совпали».

### Файлы сайта (Beget, Reg.ru)

1. Установите **WinSCP** (https://winscp.net) или FileZilla.
2. Подключитесь к хостингу (протокол SFTP, те же сервер/логин/пароль).
3. Скопируйте содержимое `снимок\files\ИМЯ\` в папку сайта на сервере
   (`mysite.ru/public_html` или `www/site.ru`).

### База данных MySQL

Файл `db\ИМЯ.sql.gz`:

* **Через phpMyAdmin** (есть в панелях Beget и Reg.ru): откройте базу → «Импорт» →
  выберите файл `.sql.gz` (phpMyAdmin понимает сжатые файлы). Если файл слишком большой
  для импорта — распакуйте его 7-Zip и загрузите по частям, или используйте способ ниже.
* **Через SSH**: загрузите файл на сервер (WinSCP) и выполните
  ```bash
  gunzip -c ИМЯ.sql.gz | mysql -u ПОЛЬЗОВАТЕЛЬ -p ИМЯ_БАЗЫ
  ```

Если сайт переезжает на **новый хостинг**: восстановите файлы и базу, затем в `wp-config.php`
поменяйте имя базы, пользователя, пароль и хост на новые.

### VPS Timeweb (сервис vybor)

1. Создайте/переустановите VPS, установите Node.js и nginx.
2. Через WinSCP скопируйте `files\vybor\` → `/opt/vybor` (включая `storage` и `.env`),
   `files\systemd\vybor.service` → `/etc/systemd/system/`,
   `files\nginx-sites\` → `/etc/nginx/sites-available/` (и ссылки в `sites-enabled`).
3. На сервере:
   ```bash
   cd /opt/vybor && npm ci --omit=dev
   systemctl daemon-reload && systemctl enable --now vybor
   nginx -t && systemctl reload nginx
   ```

### Из зашифрованной второй копии

Откройте `.7z` архив в 7-Zip, введите пароль архива — внутри тот же снимок.

## 10. Вторая копия и шифрование

Основная копия на одном диске не защищает от поломки этого диска, кражи ноутбука
или вируса-шифровальщика. Поэтому:

```yaml
second_copy:
  path: "E:\\Backups"      # внешний диск, или папка Яндекс.Диска / OneDrive
  encrypt: true            # архив 7-Zip, зашифрованный AES-256 (нужен 7-Zip)
  password_secret: archive-password
  keep: 3
```

После каждой успешной копии программа положит туда архив снимка. Пароль архива
задаётся в меню → 5 или на странице «Пароли». **Запишите его на бумаге** и храните
отдельно — без него архив не открыть.

Пока вторая копия не настроена или диск не подключён, отчёт и окно управления
показывают предупреждение «Копия лежит только на одном диске».

## 11. Уведомления в Telegram

1. В Telegram напишите **@BotFather** → `/newbot` → получите токен.
2. Напишите своему боту любое сообщение, затем узнайте свой chat_id (например через **@userinfobot**).
3. В `config.yaml`:
   ```yaml
   telegram:
     enabled: true
     chat_id: "123456789"
     notify: always      # или errors — только при проблемах
   ```
4. Токен бота введите в меню → 5 (имя `telegram-bot-token`).

## 12. Безопасность

* Пароли, токены и пароль SSH-ключа хранятся **только** в Диспетчере учётных данных Windows
  (Панель управления → Диспетчер учётных данных → Учётные данные Windows → `odaa-backup`).
  В `config.yaml` их писать нельзя — программа откажется запускаться, если увидит `password:`.
* Пароли не попадают в журнал и отчёты (вырезаются автоматически).
* Пароль базы не передаётся в командной строке на сервере: `mysqldump` получает его
  через защищённый канал SSH (stdin).
* Отпечаток каждого сервера проверяется. При неизвестном или **изменившемся** отпечатке
  копирование не выполняется, пока вы его не подтвердите.
* Окно управления открывается только на `127.0.0.1` и защищено от действий с чужих сайтов.
* Программа только читает с серверов. Удаляет она только свои старые снимки на вашем диске.
* Файл `.env` с VPS содержит секреты сервиса — храните папку бэкапов на диске с ограниченным
  доступом и включите шифрование второй копии.
* Для VPS по возможности используйте отдельного пользователя с правами только на чтение
  нужных папок вместо `root`.

## 13. Если что-то не работает

| Сообщение | Что делать |
|---|---|
| `Сервер … ещё не проверен` | Меню → 5 или окно управления → «Проверить отпечаток» → «Доверять». |
| `Отпечаток сервера … ИЗМЕНИЛСЯ` | Не подтверждайте сразу! Спросите поддержку хостинга, переустанавливали ли сервер. |
| `не задан пароль/токен «…»` | Страница «Пароли» или `odaa-backup.exe secret set ИМЯ`. |
| `сервер отклонил логин/пароль` | Проверьте логин и пароль SSH; включён ли SSH в панели хостинга. |
| `mysqldump завершился с кодом 2 … Access denied` | Неверный пароль/пользователь базы. Сверьте с `wp-config.php`. |
| `… using password: NO` | Добавьте в блок `mysql:` строку `password_via: env`. |
| `на сервере не найден mysqldump` | Узнайте у поддержки путь (например `/usr/bin/mysqldump`) и укажите `mysqldump: /usr/bin/mysqldump`. |
| `в дампе нет ни одного CREATE TABLE` | База пустая. Если так и должно быть — `allow_empty: true`. |
| `нет доступа к папке …` | Это предупреждение: часть служебных папок хостинга закрыта. Если это нужная папка — проверьте путь. |
| `Копирование уже выполняется` | Дождитесь окончания (или Планировщик как раз запустил копию). |
| Окно управления не открывается | Порт 8765 занят — поменяйте `ui: port:` в config.yaml. |

Подробности всегда есть в журнале: окно управления → «Журнал», или файл `data\logs\odaa-backup.log`.

## 14. Для разработчика

Python 3.12+, зависимости: `paramiko` (SSH/SFTP), `keyring` (Диспетчер учётных данных), `PyYAML`.
Интерфейс — встроенный `http.server`, без внешних фреймворков.

```
odaa_backup/
  cli.py          меню и команды
  config.py       разбор и проверка config.yaml, overrides из интерфейса
  schedule.py     расписание по источникам, задача Планировщика Windows
  runner.py       выполнение: снимок → файлы → дампы → манифест → ротация → 2-я копия → отчёт
  sync.py         инкрементальная загрузка по SFTP (жёсткие ссылки, докачка, повторы, лимит скорости)
  ssh.py          подключение, проверка отпечатков (known_hosts), sha256sum на сервере, генерация ключа
  mysql.py        mysqldump через SSH → .sql.gz, проверка дампа
  manifest.py     манифест SHA-256 и проверка снимка
  retention.py    ротация last/daily/weekly/monthly
  apis.py         списки бэкапов Beget / Timeweb Cloud / ISPmanager (только чтение)
  archive.py      вторая копия (7-Zip AES-256)
  report.py       отчёт и Telegram
  webui.py        окно управления (127.0.0.1)
  secretstore.py  пароли в keyring, вырезание секретов из логов
tests/            тесты: целостность, ротация, конфиг, расписание, синхронизация
```

Запуск из исходников и тесты:

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m odaa_backup --config config.yaml run --dry-run
```

Команды:

```
odaa-backup run [--source ID] [--dry-run] [--scheduled]
odaa-backup ui | status | setup | check | keygen | init
odaa-backup trust ID | test ID | verify ID [СНИМОК]
odaa-backup secret set|delete|list [ИМЯ]
odaa-backup schedule install|remove|status
```

Сборка .exe: `build.bat` на Windows или GitHub Actions (`.github/workflows/build.yml`)
при каждом push; для тега `v*` создаётся релиз с zip-архивом.
